## Confirmed issues, prioritized

| Priority | Confirmed issue | Evidence | Corrective guidance |
|---|---|---|---|
| **P1 — inquiry routing** | `?type=investment` and `?type=student-housing` are not consumed by Contact. All CTA links reach `/contact/`, but the selector always starts at **General question**. An email created from any of those links will therefore identify itself as `Inquiry type: General question` unless the visitor manually changes it. This does **not** create a backend submission, but it breaks the intended contextual inquiry path. | Contextual links occur throughout the new pages, e.g. `src/app/invest/page.tsx:185`, `src/app/student-housing/page.tsx:62`, `src/app/investment-disclosures/page.tsx:34`, and `src/app/edmonton-multiplex-lp-1/page.tsx:118`. `src/components/marketing/ContactForm.tsx:24-31` hard-codes `inquiryType: "general-question"`; the component/page has no search-parameter reader. `src/lib/inquiry.ts:135-153` puts that selected value into the email draft. | On the client, read only the `type` query parameter, accept it only when `isInquiryType(type)` returns true, and initialize/update the select to that value; retain `general-question` for missing or invalid values. Keep the control a `type="button"` draft creator and preserve the current `mailto:`-only flow—no API, storage, account, upload, or form submission is needed. Add a focused regression for valid investment/student-housing deep links and invalid fallback. |
| **P2 — invalid nested main landmarks** | Four remaining pages render a `<main>` inside the root layout’s existing `<main id="main-content">`. This creates invalid nested main landmarks and contradicts the accessibility page’s semantic-landmark statement. | Root landmark: `src/app/layout.tsx:52-54`. Nested landmarks: `src/app/accessibility/page.tsx:25,114`; `src/app/edmonton-multiplex-lp-1/page.tsx:17,121`; `src/app/investment-disclosures/page.tsx:17,115`; `src/app/privacy-policy/page.tsx:15,65`. This is the already-identified parent integration cleanup; no content or homepage CSS change is required. |

This is **not a preview blocker**.
- **Contact remains truthful and non-transactional:** `ContactForm` performs local validation, clipboard copy, and a URI-encoded `mailto:` draft only. Source sweep found no `fetch`, API client, persistence store, database, upload, account, payment, or private-backend integration in `src/`.

The inspected page CSS provides one-/two-/three-/four-column breakpoint treatments, mobile controls, focus styles, scroll margins, and global reduced-motion handling. No source-level broken target was found.

The parent-owned static build is therefore the appropriate place to refresh and verify it; this review did not treat that generated prebuild artifact as a page-source defect.
